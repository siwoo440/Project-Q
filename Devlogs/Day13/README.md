## 조건부 유물 시스템

### RelicTriggerType

유물 발동 시점을 분리했다.

- `Passive`
- `OnCardUsed`
- `OnEnemyKilled`
- `OnPlayerHit`
- `OnDodge`
- `OnCombatStart`
- `OnCombatClear`

12일차의 단순 능력치 패시브는 `Passive`로 유지한다.

### RelicRuntimeState

조건부 유물마다 별도 런타임 상태를 관리한다.

관리 항목:

- 조건 충족 누적 횟수
- 내부 쿨타임
- 발동 가능 상태

내부 쿨타임 중 발생한 조건은 추가 누적하지 않는다.

### RelicEventController

다음 전투 이벤트를 수신해 현재 보유 유물을 검사한다.

- 카드 사용 성공
- 적 처치
- 플레이어 피격
- 회피 성공
- 전투 시작
- 전투 클리어

`RelicInventory`의 보유 유물과 `RelicRuntimeState`를 조합해 실제 발동 가능 여부를 결정한 뒤 `RelicEffectController`로 효과를 실행한다.

## 전투 이벤트 연결

### CardUseController

## ShopController

실제 구매 트랜잭션을 관리한다.

구매 흐름:

`상품 선택 → 골드 확인 → TrySpendGold → 상품 적용 → 구매 완료`

지원 구매:

- `RunDeck.AddCard()`를 이용한 카드 구매
- `RelicInventory.TryAddRelic()`을 이용한 유물 구매
- `PlayerStats.Heal()`을 이용한 회복 구매
- `RunDeck.TryRemoveCard()`를 이용한 카드 제거 서비스

상품 적용에 실패하면 차감한 골드를 다시 반환한다.

골드가 부족하면 구매를 차단하고 골드는 변경하지 않는다.

## 카드 제거 서비스

카드 제거 상품을 선택한 뒤 별도의 카드 선택 상태로 전환한다.

조작:

- `↑ / ↓`: 제거 카드 선택
- `Enter`: 제거 확정
- `B / ESC`: 제거 취소

카드 제거 결제 후 실제 제거에 실패하면 골드를 전액 환불한다.

최소 Q/E 활성 슬롯 수보다 덱이 작아지는 제거는 기존 RunDeck 규칙으로 차단한다.

상점을 닫으면 조작을 복구하고 `Arena.BeginCombat()`으로 다음 전투를 시작한다.

## 카드 조작 변경

기존 카드 사용 방식:

`Q / E 슬롯 선택 → 좌클릭 사용`

13일차 최종 입력 방식:

- 마우스 좌클릭: 왼쪽 활성 카드 즉시 사용
- 마우스 우클릭: 오른쪽 활성 카드 즉시 사용

실제 플레이에서는 Q/E 선택 단계를 사용하지 않는다.

`SelectSlot()`과 `TryUseSelectedCard()`는 이전 Editor Setup 및 코드 호환을 위해 유지하지만 런타임 마우스 입력에서는 사용하지 않는다.

## 카드 HUD 변경

기존 선택 강조와 Q/E 선택 문구를 제거했다.

현재 안내:

`좌클릭 : 왼쪽 카드 | 우클릭 : 오른쪽 카드`

각 슬롯에도 `좌클릭` 또는 `우클릭`이 직접 표시된다.

카드 상태는 기존처럼 다음 정보를 유지한다.

- MP 비용
- 사용 가능
- MP 부족
- 쿨타임
- 강화 단계

## 컴파일 오류 수정

13일차 초기 구현에서 `PlayerDodge`에 조건부 유물용 `Dodged` 이벤트를 추가하는 과정에서 12일차에 존재하던 다음 API가 누락됐다.

- `ResetDodge()`
- `CooldownDuration`

이 때문에 다음 참조에서 `CS1061`이 발생했다.

- `CombatFlowController`
- `CombatHUDController`

최종 수정에서는 기존 회피 API를 복원하면서 `Dodged` 이벤트를 함께 유지했다.
